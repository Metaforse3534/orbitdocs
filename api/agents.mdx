The Agents API exposes two endpoints that let you run Orbit's autonomous AI agents programmatically. Start a run by POSTing a task to your chosen agent, then poll the status endpoint until the run completes and retrieve the result. This asynchronous design lets agents work through long-running tasks — research, report generation, multi-step analysis — without blocking your application.

## Endpoints

| Method | Path | Description |
|---|---|---|
| `POST` | `/v1/agents/{agentId}/runs` | Start a new agent run |
| `GET` | `/v1/agent-runs/{runId}` | Check run status and retrieve the result |

---

## Start an Agent Run

```
POST https://api.orbitdev.org/v1/agents/{agentId}/runs
```

Submit a task to a specific agent. The agent is identified by its `agentId`, which you can find in the agent detail view inside the [Orbit workspace](https://app.orbitdev.org).

### Path Parameters

<ParamField path="agentId" type="string" required>
  The unique identifier of the agent to run. Agent IDs are prefixed with `agt_` and are displayed in the workspace UI on each agent's detail page.
</ParamField>

### Request Body

<ParamField body="input" type="string" required>
  The task or instruction to pass to the agent. Write this as a clear, specific description of what you want the agent to accomplish — the more precise the input, the better the result.
</ParamField>

<ParamField body="mode" type="string">
  Model routing mode for this run. Accepts the same values as the chat completions endpoint: `"auto"`, `"normal"`, `"orbit"`, `"pulsar"`, or `"pro"`. Defaults to `"auto"`.
</ParamField>

### Example Request

```bash
curl -X POST https://api.orbitdev.org/v1/agents/agt_abc123/runs \
  -H 'Authorization: Bearer orb_your_api_key' \
  -H 'Content-Type: application/json' \
  -d '{"input": "Research the top 5 electric vehicle manufacturers and write a comparison report."}'
```

### Example Response

```json
{
  "runId": "run_xyz789",
  "status": "queued",
  "agentId": "agt_abc123"
}
```

Save the `runId` from this response — you will use it to poll for the run result.

## Check Run Status

```
GET https://api.orbitdev.org/v1/agent-runs/{runId}
```

Retrieve the current status of an agent run. Poll this endpoint until `status` is `"completed"` or `"failed"`.

### Path Parameters

<ParamField path="runId" type="string" required>
  The unique identifier of the run to check. This is the `runId` value returned by the start run call, prefixed with `run_`.
</ParamField>

### Run Status Values

| Status | Description |
|---|---|
| `queued` | The run has been accepted and is waiting to be picked up by an agent worker. |
| `running` | The agent is actively working on the task. |
| `completed` | The agent has finished successfully. The `result` field contains the output. |
| `failed` | The agent encountered an error. Inspect the `error` field for details. |

### Example Request

```bash
curl https://api.orbitdev.org/v1/agent-runs/run_xyz789 \
  -H 'Authorization: Bearer orb_your_api_key'
```

### Example Response (Completed)

```json
{
  "runId": "run_xyz789",
  "agentId": "agt_abc123",
  "status": "completed",
  "result": "The top 5 electric vehicle manufacturers are...",
  "createdAt": "2024-01-01T10:00:00Z",
  "completedAt": "2024-01-01T10:02:30Z"
}
```

### Response Fields

<ResponseField name="runId" type="string">
  The unique identifier for this run.
</ResponseField>

<ResponseField name="agentId" type="string">
  The identifier of the agent that processed this run.
</ResponseField>

<ResponseField name="status" type="string">
  Current run status: `queued`, `running`, `completed`, or `failed`.
</ResponseField>

<ResponseField name="result" type="string">
  The agent's output. Present only when `status` is `"completed"`.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp of when the run was created.
</ResponseField>

<ResponseField name="completedAt" type="string">
  ISO 8601 timestamp of when the run finished. Present only when `status` is `"completed"` or `"failed"`.
</ResponseField>

## Polling Pattern

Use a loop that checks the status endpoint at a regular interval, then processes the result once the run is complete:

```javascript
async function waitForAgentRun(runId, intervalMs = 3000, timeoutMs = 300000) {
  const start = Date.now();

  while (Date.now() - start < timeoutMs) {
    const response = await fetch(`https://api.orbitdev.org/v1/agent-runs/${runId}`, {
      headers: { 'Authorization': `Bearer ${process.env.ORBIT_API_KEY}` },
    });

    const run = await response.json();

    if (run.status === 'completed') return run.result;
    if (run.status === 'failed') throw new Error(`Agent run failed: ${run.error}`);

    // Wait before polling again
    await new Promise(resolve => setTimeout(resolve, intervalMs));
  }

  throw new Error('Agent run timed out');
}

// Usage
const runResponse = await fetch('https://api.orbitdev.org/v1/agents/agt_abc123/runs', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${process.env.ORBIT_API_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ input: 'Summarise the latest AI research papers on RAG.' }),
});

const { runId } = await runResponse.json();
const result = await waitForAgentRun(runId);
console.log(result);
```

<Tip>
  Poll at intervals of 2–5 seconds rather than as fast as possible. Flooding the status endpoint with rapid requests consumes your per-minute rate limit without speeding up the agent. A 3-second interval is a good default for most tasks.
</Tip>

<Note>
  Agent runs on complex or research-intensive tasks may take 1–5 minutes to complete. The `completedAt` timestamp in the response tells you the exact duration of each run, which can help you calibrate timeout values in your polling logic.
</Note>
